I use the [Comprehensive Aramaic Lexicon (CAL)](https://cal.huc.edu/) for lexical and textual research. It covers Aramaic across many periods and dialects, with dictionaries, texts, citations, concordances, and bibliographic resources. There's a great deal of material there, although moving between the lexicon, a text, and its citations often involves several separate searches.

I wrote [CAL-MCP](https://github.com/alexsosn/CAL-MCP) to make those searches available through the [Model Context Protocol (MCP)](https://modelcontextprotocol.io/). The idea is straightforward: an MCP-compatible assistant can request specific CAL data, receive structured results, and use them to help with a research question. You can still open the original CAL pages to check the evidence.

## How it works

MCP lets an application use tools supplied by an external program. CAL-MCP is a local, read-only server that exposes CAL research functions as tools. Your MCP client calls one of them, the server makes a bounded request to CAL's public website, and it returns the result with the CAL source URL and retrieval time.

The server does **not** include a copy of CAL's database, and installing it does not download the corpus. CAL remains the source of the lexical entries, textual readings, and bibliographic records. CAL-MCP also doesn't create its own linguistic analyses or silently resolve ambiguities in CAL's data.

Here are a few things you can do with it. The tool calls below illustrate actual interfaces in the published release; they are examples of requests, not transcripts of a live research session.

## 1. Look up a word, then check where it occurs

Suppose I'm looking at the form `br` and want to inspect its lexical entries. I can ask an MCP client:

> Look up `br` in CAL. Show me the available entries and their source links. If there are several possible lemmas, don't choose one without asking.

The first operation is:

```text
cal_lexicon_lookup(query="br")
```

CAL may return more than one candidate. Those candidates have CAL lemma keys, which can be used in subsequent searches. Once I've selected the relevant entry, I can ask for its distribution across dialects and then inspect one dialect's concordance:

```text
cal_kwic_dialects(lemma_key="<selected CAL lemma key>")
cal_kwic_dialect(
    lemma_key="<selected CAL lemma key>",
    dialect_id="<dialect ID from the previous result>"
)
```

The distinction between a form, a selected lemma, and an attestation matters. CAL-MCP preserves that distinction rather than presenting all similar spellings as one word.

You can also begin in English. For example, `cal_gloss_search(query="camel#")` searches CAL's English gloss index and returns candidate lemmas to investigate. This is useful when I know what I'm looking for semantically but not how the word is spelled in a particular Aramaic dialect.

## 2. Move from a text to a particular word

CAL has browsable texts as well as lexical entries. For example, I can search for the Tel Dan inscription:

```text
cal_text_search(query="Tel Dan")
```

I then select a returned text identifier and retrieve its page:

```text
cal_text_page(file_id="<file_id returned by CAL>")
```

For words with CAL machine coordinates, `cal_token_analysis` can retrieve the analyses attached to a **specific token**. If CAL provides multiple analyses, the tool returns those alternatives; it doesn't decide which interpretation is best.

This makes it possible to follow a fairly ordinary philological workflow: find a text, inspect a passage, check a word, and open the relevant lexical entry. The steps stay separate, so I can see what was actually requested from CAL.

## 3. Compare Targums and Syriac biblical texts

CAL also provides specialized research interfaces for Targums and Syriac. For a biblical verse, I can request CAL's available Targum parallels:

```text
cal_targum_parallel(book="Gen", chapter=1, verse=1)
```

For the corresponding Masoretic Text / Syriac Peshitta view, there's a separate tool:

```text
cal_syriac_peshitta_parallel(book="Gen", chapter=1, verse=1)
```

An assistant can put the retrieved readings side by side and help identify differences worth investigating. Any explanation of those differences is the assistant's interpretation, not an analysis supplied or endorsed by CAL.

There are more specialized options too: `cal_targum_concordance` for a lemma in Targum sources, `cal_targum_hebrew_lemmas` followed by `cal_targum_hebrew_reflexes` for CAL's Hebrew-to-Aramaic reflex data, and `cal_syriac_texts` for navigating Syriac text categories.

## 4. Follow the bibliography

A lexical question often leads to a bibliographic one. CAL-MCP has tools for searching CAL's bibliography by author, subject/text tag, or lemma. For a lemma already identified in the lexicon, I can use:

```text
cal_bibliography_lemma(lemma_key="<selected CAL lemma key>")
```

This returns CAL's bibliographic records for that key. The result is a starting point for checking the cited publications, not a substitute for reading them.

## Installing CAL-MCP

The first release, **v0.1.0**, is [published on PyPI](https://pypi.org/project/cal-mcp/0.1.0/) and provides 36 public tools. It requires Python 3.11 or newer. Install it with:

```bash
python -m pip install "cal-mcp==0.1.0"
```

You can check the installation without starting the server:

```bash
cal-mcp --version
```

Then configure your MCP client to start `cal-mcp` as a **stdio** server, with no command-line arguments. It runs as a local process and needs internet access to `cal.huc.edu` when you make a CAL-backed request. The exact client configuration depends on the application you're using; see the [installation guide](https://github.com/alexsosn/CAL-MCP/blob/main/docs/installation.md) and [standalone MCP instructions](https://github.com/alexsosn/CAL-MCP/blob/main/docs/integrations/standalone-mcp.md).

The repository's development branch can contain features not present in the released package, so the tool names and installation instructions above refer to the published **0.1.0** version.

## A few limitations

CAL is an ongoing scholarly project. Its records can be corrected or expanded, and its website is not a versioned machine API. CAL-MCP therefore keeps source URLs and retrieval timestamps with its results and reports unexpected upstream changes instead of treating them as empty search results.

The requests are deliberately bounded: there is no automatic harvesting of entire corpora, background crawling, or local CAL mirror. Each follow-up—opening an entry, inspecting a citation, loading another text page—is an explicit operation.

For research work, I would keep the original CAL links, the date of retrieval, and the identifiers associated with any quotation or analysis. And, of course, I would verify any argument proposed by an AI assistant against the primary text and the scholarly literature.
